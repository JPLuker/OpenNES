# Building and testing OpenNES

OpenNES is an early-stage fork of Lemuroid. These instructions build its development APK. The current NES-only source paths package FCEUmm. The consolidated `master` workflow passed lint, build, NES-only inspection and publication on [commit `5dd2fac`](https://github.com/JPLuker/OpenNES/commit/5dd2fac586863858b6b1d1f71fa44a387bf10007); **full device acceptance remains open**.

## Requirements

- JDK 17
- Android SDK installed and accessible to Gradle (`ANDROID_HOME` or `local.properties`)
- A recent version of Python 3 to inspect APK contents
- Git, including support for submodules
- Android phone or emulator, with ADB for convenient installation

The Gradle wrapper is included in the repository; use it rather than installing a separate Gradle version.

## Fetch source

```sh
git clone --recurse-submodules https://github.com/JPLuker/OpenNES.git
cd OpenNES
```

If you already cloned without submodules:

```sh
git submodule update --init --recursive
```

Development proceeds by direct commits to `master`; use a pinned commit for reproducible troubleshooting rather than an unverified rolling branch.

## Compile an installable debug APK

```sh
./gradlew :lemuroid-app:assembleFreeBundleDebug --stacktrace
```

On Windows, use `gradlew.bat :lemuroid-app:assembleFreeBundleDebug`.

Look in `lemuroid-app/build/outputs/apk/freeBundle/debug/` for an `.apk`. The `freeBundleDebug` variant is used because it does not need the Play Store's dynamic-download arrangement or release signing credentials.

The current debug package ID is `com.jpluker.opennes.debug`. **Do not install the old upstream Lemuroid release APK and assume it is OpenNES.**

## M5 final-testing protocol

For a complete M0–M5 freeze checklist, use [M5 final-testing handoff](M5_FINAL_TESTING.md). Only test the exact source commit after CI has passed build, lint and APK inspection. Preserve existing game saves before upgrading. This is not a production release.

## Install and smoke test

To install an APK directly:

```sh
adb devices
adb install -r /absolute/path/to/generated-debug.apk
```

Use the actual APK filename generated by Gradle. Validate these behaviors on your device:

1. Android shows the **OpenNES** app label, and the debug app installs alongside any existing Lemuroid installation.
2. A legally obtained NES `.nes` game can be imported and launched.
3. D-pad, diagonal inputs, A/B, Start and Select respond.
4. Game audio, basic save functionality and screen rotation work.
5. Backgrounding and resuming the game do not crash.

M2 replaced the old user-facing interface in source. Verify that every visible screen is OpenNES-branded when device testing resumes; no such acceptance is being claimed here.

## Automatic APK downloads

**Direct download:** [OpenNES-debug.apk](https://github.com/JPLuker/OpenNES/releases/download/dev-latest/OpenNES-debug.apk)

The [OpenNES Android CI workflow](https://github.com/JPLuker/OpenNES/actions) runs for pushes to `master` or manual dispatch. **One job** runs Kotlin lint, builds the NES-only debug APK, verifies its contents, generates a SHA-256 checksum and publishes to the single rolling [`dev-latest` release](https://github.com/JPLuker/OpenNES/releases/tag/dev-latest). There is **no second APK workflow artifact** or separate M5-candidate download.

Use only the direct `dev-latest` APK link above for normal testing. Its filename and URL never change. Each successful upload includes [the matching checksum](https://github.com/JPLuker/OpenNES/releases/download/dev-latest/OpenNES-debug.apk.sha256). A failed lint/build does not overwrite the last successfully published APK. Check the release notes for the source commit before reporting regressions. The workflow uses the built-in GitHub token for upload; **no production signing key is involved**.

The download uses package ID `com.jpluker.opennes.debug`, signed with the repository's existing development keystore. Do not expect it to update a future production build with application ID `com.jpluker.opennes` directly.


## Optional production release signing (M8 — not yet accepted)

The `release` variant has **no default signing key**. Configure it only for a real production release; never commit a keystore, passwords, exported private key, or credentials. These variables must all be present:

- `OPENNES_RELEASE_KEYSTORE` — absolute path to the private release keystore
- `OPENNES_RELEASE_STORE_PASSWORD`
- `OPENNES_RELEASE_KEY_ALIAS`
- `OPENNES_RELEASE_KEY_PASSWORD`

For example, provide them through a private local shell/CI secret store and only then invoke `./gradlew :lemuroid-app:assembleFreeBundleRelease`. Without all four values, Gradle should create an **unsigned** release artifact. **Do not publish either artifact until production signing, provenance, licenses, installation, upgrade, rollback, and full device acceptance have been independently verified.** OpenNES's debug signing and rolling development APK mechanism are unchanged.

## Inspect the core bundle

```sh
python3 scripts/inspect-apk.py /absolute/path/to/OpenNES-debug.apk
```

The script prints the APK size, native libraries and each packaged Libretro core. For NES-only verification, run:

```sh
python3 scripts/inspect-apk.py --nes-only /absolute/path/to/OpenNES-debug.apk
```

That command will fail if the FCEUmm core is absent or if any other Libretro core remains.

## NES-only metadata in packaged CI builds

GitHub Actions runs `python3 scripts/trim-libretro-db.py --in-place lemuroid-metadata-libretro-db/src/main/assets/libretro-db.sqlite` in its temporary checkout. The script retains NES records, checks database integrity and vacuums the SQLite file.

Local Gradle builds do not automatically trim this asset. To reproduce the slim CI build, run the command explicitly before Gradle; `git restore lemuroid-metadata-libretro-db/src/main/assets/libretro-db.sqlite` restores the tracked original afterward.

The CI-packaged database has 29,246 NES records (3,706,880 bytes), down from 104,073 records (12,775,424 bytes).

## Troubleshooting

**The rolling APK did not update.** The consolidated job must pass lint, compilation and APK inspection before updating `dev-latest`. Check [GitHub Actions](https://github.com/JPLuker/OpenNES/actions); the last successful APK remains available.

**The Gradle task can't find core libraries.** Run `git submodule update --init --recursive` and confirm `lemuroid-cores/bundled-cores` exists.

**JDK/Android SDK error.** Verify `java -version` reports JDK 17, that the Android SDK is installed, and that its path is configured.

**Signing error.** Use the debug variant. OpenNES will not fall back to inherited release signing credentials. The optional release configuration requires all four environment variables documented below; otherwise the release variant is unsigned.

**APK is unexpectedly large.** The M0 baseline measured 222,012,846 bytes; the first NES-only M1 APK measured 35,346,475 bytes, and the trimmed-metadata build measured **32,367,426 bytes**. Inspect the included cores using the script above.

**ROM won't start.** Test with a known-good, legally obtained NES test ROM; note the file type and capture logs. Do not assume that an unrelated console ROM should work in the final NES-only build.

## Known limitations

OpenNES now has NES-only packaging and the M2–M4 source UI/controller implementation, but native RetroAchievements are not integrated. Production APK signing, native dependency audit, and all build and device acceptance remain outstanding. See [ROADMAP.md](../ROADMAP.md).
